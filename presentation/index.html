o tema02 / 12
o problema

O hardware dura. O software é que vence.

Um celular é um computador ARM64 com 8 núcleos, GPU e 8 GB de RAM. O fabricante para de atualizar em 2–4 anos e o aparelho vira lixo eletrônico — com o hardware intacto.

android

Linux com outro userspace

Bionic no lugar da glibc · ART para apps · HAL entre sistema e driver · SurfaceFlinger em vez de Wayland.

Kernel downstream, com milhares de patches do fabricante. Ele para de atualizar, acabou.

linux convencional

A mesma pilha do desktop

glibc ou musl · processos POSIX · Wayland · systemd · gerenciador de pacotes de verdade.

Kernel mainline: recebe correção enquanto o código estiver na árvore oficial do Linux.

A pergunta do trabalho: dá para rodar o segundo num celular? Três projetos respondem de formas diferentes.

fundamentação03 / 12
a pilha de um Linux móvel

Quatro camadas entre o silício e o dedo.

shell móvel
Phosh 0.58 + Phoc — a interface adaptada a tela pequena e toque. Alternativa: Plasma Mobile.
exibição
Wayland — protocolo que substituiu o X11. O compositor Phoc fala direto com o DRM/KMS e submete à GPU via Mesa / Freedreno.
telefonia
ModemManager sobre QMI/QRTR conversa com o modem; NetworkManager cuida dos dados. Alternativa: oFono (Ubuntu Touch).
userspace
Alpine Linux + apk + systemd — 1326 pacotes, repositórios assinados.
kernel
Linux 7.2.9 mainline (família sc7280) — sem blobs Android. Device Tree descreve o dubai; 4 co-processadores Qualcomm sobem: modem, ADSP, WPSS, CDSP.

O desafio real: drivers. O SoC é suportado upstream, mas câmera, NFC e háptica dependem de código que ainda não foi mesclado.

as três04 / 12
quem está no jogo

Três respostas para a mesma pergunta.

01 · alpine

postmarketOS

Compromisso com kernel mainline e o maior alcance: 300+ aparelhos, a maioria em testing. Interface Phosh ou Plasma Mobile. Rebatizado Nura em set/2026.

+ vida longa ao aparelho
− maturidade varia muito

02 · debian

Mobian

Não é distro nova: é o Debian com pacotes para hardware móvel. Mesma apt, mesma cultura de estabilidade. Phosh, kernel mainline.

+ estabilidade Debian
− poucos aparelhos (PinePhone, PineTab)

03 · ubports

Ubuntu Touch

Interface própria (Lomiri), telefonia madura, ~111 aparelhos. Usa Halium: reaproveita kernel e drivers Android do fabricante.

+ melhor experiência de uso
− herda o kernel congelado

Todas usam Wayland. Duas usam ModemManager; Ubuntu Touch usa oFono. A diferença de fundo está no kernel.

por que escolhemos

postmarketOS era a única das três com port do Edge 30 e kernel mainline — sem camada de compatibilidade Android.

trade-off

Ganhamos independência de blobs; pagamos em maturidade: o dubai é testing.

leitura

Ubuntu Touch entregaria telefonia mais pronta; Mobian, mais estabilidade — nenhum roda neste aparelho.

análise06 / 12
a divisão que realmente importa

Não é a interface. É o kernel.

caminho mainline

postmarketOS · Mobian

Escrevem o Device Tree e usam drivers da árvore oficial. Dá muito mais trabalho por aparelho e a maturidade varia — mas o aparelho continua recebendo kernel novo enquanto o código estiver no Linux.

caminho halium

Ubuntu Touch

Reaproveita kernel e drivers Android. Habilita um aparelho muito mais rápido — e o congela na versão de kernel que o fabricante deixou. Perpetua o problema que motivou o projeto.

quero usar hoje

Ubuntu Touch — se o seu aparelho estiver no catálogo.

quero estabilidade

Mobian — em hardware feito para Linux.

quero vida longa

postmarketOS — e foi a única com port do nosso aparelho.

Ressalva honesta: nenhuma das outras duas roda no Edge 30. Comparamos projetos — não três sistemas no mesmo hardware.

execução08 / 12
como se instala na prática

Dois mundos: a VM que fabrica, o PC que grava.

na vm ubuntu

pmbootstrap

A ferramenta oficial monta o sistema por cross-compile: init escolhe device, kernel e interface; build gera boot.img, dtbo.img e o rootfs.

no pc windows

fastboot

Bootloader destravado pela Motorola, AVB desabilitado, overlays Android apagados e as imagens gravadas nas partições.

01 · preparar
Destravar o bootloader (chave OEM da Motorola) e conferir a variante do painel — csot ou tianma.
02 · construir
pmbootstrap init + build → três imagens com sha256 conferido.
03 · gravar e bootar
Gravação por fastboot, primeiro boot em Linux, Wi-Fi configurado e sshd no ar.

Ressalva honesta: o método oficial hoje usa U-Boot + USB mass storage. O nosso caminho foi o fastboot direto — funciona, mas diverge da wiki.

diagnóstico10 / 12
dificuldades reais

Problemas de quem opera — e o que generaliza.

o relato que investigamos

"Baixa responsividade"

A wiki registra relatos de lentidão no kernel sc7280-mainline. Fomos medir: o toque responde — 6942 eventos capturados. A CPU fica 97% ociosa e a GPU acelera até 608 MHz.

O que realmente atrapalha o uso diário é outro: a suspensão trava o aparelho.

a lição que generaliza

Cada caso é um caso

postmarketOS lista 300+ aparelhos — a maioria em testing. "Suporta o seu modelo" não quer dizer que tudo funciona: depende de quem escreveu o driver daquele periférico.

Nossa matriz vale para este Edge 30. Em outro aparelho da mesma distro, o resultado pode ser bem diferente.

obstáculo → solução

Sem imagem pronta

Device testing, sem build oficial. → Build próprio na VM.

obstáculo → solução

Reconexão falhou

O IP mudou por DHCP. → Identificação pela chave de host SSH.

Por isso o comparativo entre distros só vai até certo ponto: a unidade real de maturidade é o aparelho, não a distribuição.
